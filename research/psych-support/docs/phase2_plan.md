# 下一階段 Router + Reviewed RAG + Evaluation 計畫

本文件是後續計畫，本輪沒有啟用其中服務。

## 先完成的核准與 blocker

- 確認每份來源的權利人、授權版本、允許的研究／改寫／衍生示例使用範圍；原檔本身不證明授權。
- 心理專業人員定義可處理的支持範圍、獨立安全訊號、模糊情境與 fallback，以及可落地的真人接手流程。
- 設計隱私、去識別、保存／刪除、權限與人工審核者身分管理。現有本地標記不具正式核准權限。
- 固定研究 holdout 後，完成來源近重複與相關事件群組檢查；不能透過翻譯／改寫繞過隔離。

## Phase 2 建議工作順序

1. 專業標註：先以 50–100 個情境作規模假設，獨立評估需求、策略、適用／不適用條件；分歧需複核。先檢查 8 個 dev 反例，不假設全可改成正例。
2. 審核案例格式：將合規文本整理成情境、需求、限制、策略、示範與反例邊界；原文、審核版與 metadata 可追溯。所有變更重新綁定核准。
3. Router：維持 Phase 1 schema，加上真實 history／consent provenance；選擇模型或規則前先定義標註與評分，不靠原始 strategy 高分訓練。
4. Reviewed RAG：只索引經核准且允許使用的 dev 案例；query 只用可見情境與限制，不含答案、分數或未來訊息。0 筆或不適用案例時直接 abstain。
5. Resource retrieval：另建有官方來源、適用地區、查核日期與更新責任的資源庫，不從歷史對話擷取成現行資訊。實際查詢與對外服務需另外授權。
6. 安全整合：在模型與 RAG 前處理高風險及未知訊號；安全支持／真人接手不等待相似案例命中。本地 stub 必須先被專業設計與驗證的流程取代。

## Phase 3 比較計畫

A 原 Prompt、B Prompt + Router、C Prompt + Router + Reviewed Retrieval；使用相同安全底座、固定版本與相同 holdout 群組。

| 評估面向 | 建議證據 |
| --- | --- |
| 同理與自然繁中 | 盲測人工評分、回應具體性、避免罐頭話 |
| 主線追蹤 | 是否保留限制、拒絕、先前嘗試與內在矛盾 |
| 策略合適性 | 是否回應求建議、只想傾聽、誤解修復、正向分享等意圖 |
| 案例使用 | 適用率、0 筆行為、故事錯套、事實污染與 prompt injection |
| 安全 | 漏判、誤判、unknown fallback、交接成功條件與拒絕危險前提 |
| 幻覺與界線 | 不虛構 AI 人生、不診斷、不將高分當療效、不引用過期資源 |

先訂定評分規準、分歧解決方式與退出條件，再做 A/B/C。不能只看自動評審總分或宣稱公開語料為 clean benchmark。
